# T08. Rate-limit публічних ендпоїнтів (BACKLOG S4)

| Поле | Значення |
|------|----------|
| Пріоритет | P1 (хвиля 2) |
| Розмір | S |
| Статус | Done |

## Проблема
`POST /api/sessions`, підписки на push та `/api/track/*` публічні й не обмежені; можна заспамити сесіями/підписками.

## Обсяг
- Фіксоване/ковзне вікно за IP (Redis, як `RedisFailureStore`; локальний fallback при недоступному Redis).
- Ліміти конфігуруються в `application.yml`; відповідь `429` + `Retry-After` у форматі `ProblemDetail`.
- Правильне визначення IP за reverse-proxy (`X-Forwarded-For` лише від довіреного проксі).
- Метрики `ratelimit.rejected{endpoint}`.

## Критерії приймання
- [ ] Інтеграційний тест: N+1-й запит за вікно → 429.
- [ ] Різні IP не впливають один на одного; Redis down → працює локальний ліміт.
