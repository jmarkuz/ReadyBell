# T06. Структурна ізоляція tenant (BACKLOG S1)

| Поле | Значення |
|------|----------|
| Пріоритет | P1 (хвиля 2) |
| Розмір | M |
| Статус | In review |

## Проблема
`enableTenantFilter(...)` викликається вручну у 17 методах репозиторіїв. Забутий виклик = витік даних між ресторанами.

## Обсяг
- Увімкнути фільтр один раз на запит (Hibernate `@TenantId` / `CurrentTenantIdentifierResolver` або фільтр сесії у `TenantResolutionFilter`).
- Видалити ручні виклики.
- Архітектурний/інтеграційний тест, що обходить усі `*JpaRepository` методи під двома tenant і падає, якщо запит повертає чужі рядки.
- Фонові потоки (push executor, housekeeping, SSE relay) явно задають tenant або працюють у «системному» режимі.

## Критерії приймання
- [ ] У `adapter/out/persistence` немає ручних `enableTenantFilter`.
- [ ] Новий метод репозиторію без tenant-захисту ламає тест.
- [ ] `TenantIsolationApiTest` та решта інтеграційних тестів зелені.
