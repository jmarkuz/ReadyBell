# T07. Одноразовий тікет для SSE замість `?token=` (BACKLOG S2)

| Поле | Значення |
|------|----------|
| Пріоритет | P1 (хвиля 2) |
| Розмір | S |
| Статус | Todo |

## Проблема
`/api/orders/stream?token=<JWT>` потрапляє в логи проксі та історію. Довгоживучий токен у URL — витік облікових даних персоналу.

## Обсяг
- `POST /api/orders/stream/ticket` (з Bearer) → `{ticket, expiresIn: 30}`; тікет зберігається в Redis (`GETDEL` при використанні), прив'язаний до користувача й tenant.
- `GET /api/orders/stream?ticket=…` приймає лише тікет; параметр `token` вилучити.
- `useSSE` запитує тікет перед (пере)підключенням.
- Маскування `ticket` у логах доступу.

## Критерії приймання
- [ ] Повторне використання та прострочений тікет → 401.
- [ ] Тікет іншого tenant не відкриває потік цього tenant.
- [ ] `useSSE.test.ts`, `SseFanoutTest` оновлені; `API_INTEGRATION.md` оновлено.
