## Проблеми (знайдені під час аналізу `IncomingOrdersTable.tsx`)
1. **Подвійне перемикання сортування (підозра, спершу відтворити тестом).** `handleSort` викликає `setSortOrder` усередині
   updater-функції `setSortField`. У `React.StrictMode` (увімкнено в `main.tsx`) updater виконується двічі, тому
   `asc → desc → asc` і повторний клік по тій самій колонці може не змінювати напрямок у dev-режимі.
2. **Сторінка не скидається** при зміні сортування або фільтрів; зараз лише обмежується (clamp) до останньої.
3. **`SortIndicator` оголошений усередині компонента** → створюється новим типом на кожен рендер і перемонтовується.
4. Заголовки колонок: `role="button"` на `<th>` ламає семантику таблиці; потрібен `<button>` усередині `<th aria-sort>`.
5. Пробіл у `onKeyDown` без `preventDefault()` скролить сторінку.

## Обсяг
- Один стан `{ field, order }` і чиста функція перемикання; тест, що ловить п. 1 під `StrictMode`.
- Скидання сторінки на 1 при зміні сортування (для керованого й некерованого режимів).
- Винести `SortIndicator` (і, за бажання, заголовок колонки) з тіла компонента.
- Заголовки: `<th aria-sort><button>…</button></th>`, `preventDefault` для пробілу.
