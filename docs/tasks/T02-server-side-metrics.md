## Проблема
`Dashboard.tsx` рахує `OrderMetrics` із завантажених замовлень («metrics calculated from all loaded orders»), тобто максимум із 100.
Після 100 замовлень картки показують неправильні числа (наприклад, «completed today»).

## Мета
Картки метрик завжди відображають реальні значення для ресторану, незалежно від розміру таблиці та фільтрів.

## Обсяг
- `GET /api/orders/metrics` → кількість по статусах, `activeCount`, `completedToday`, середній час очікування (за потреби).
  Дані з агрегуючого запиту, tenant-ізольовано. Межі «сьогодні» — часовий пояс ресторану (`RestaurantConfig`) або UTC, зафіксувати рішення.
- Метод у `OrderQueryUseCase` (разом з A1 із BACKLOG, якщо ще не зроблено).
- Фронтенд: хук `useOrderMetrics`, оновлення за SSE; видалити клієнтський розрахунок.

## Критерії приймання
- [ ] Для 300 замовлень з різними статусами числа збігаються з БД.
- [ ] Фільтри таблиці не впливають на картки.
- [ ] Інтеграційний тест: метрики не включають замовлення іншого tenant.
- [ ] Поле `OrderMetrics` у `types/index.ts` відповідає відповіді API; `docs/API_INTEGRATION.md` оновлено.
