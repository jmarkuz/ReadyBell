# T09. Тести application-шару та підвищення порогу покриття

| Поле | Значення |
|------|----------|
| Пріоритет | P2 (хвиля 3) |
| Розмір | M |
| Статус | Done |

## Проблема
Юніт-тести є лише для доменів і `OrderReadyHandler`. Сервіси `ManageOrderService`, `TrackSessionService`,
`RestaurantAdminService`, `PlatformAdminService` покриті лише інтеграційними тестами. Поріг JaCoCo — 75 % рядків / 65 % гілок.

## Обсяг
- Юніт-тести сервісів із in-memory репозиторіями (за зразком `InMemoryOrderRepository`): помилкові гілки, tenant-перевірки, переходи станів.
- Виміряти поточне покриття та підняти пороги в `build.gradle` (ціль: 85 % / 75 %), не знижуючи інших правил.
- Мутаційне тестування (PIT) на `ordering.domain` — опційно, окремо.

## Критерії приймання
- [ ] Кожен public-метод use case має щонайменше один тест на успіх і на помилку.
- [ ] `./gradlew check` проходить із новими порогами.
