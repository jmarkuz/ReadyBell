MULTI-TENANT SUPPORT

- All orders scoped to authenticated tenant
- Query-layer enforcement (real backend uses Hibernate @Filter)

ERROR HANDLING

================================================================================
KEY DECISIONS MADE
================================================================================

1. Bearer Token Authentication
   - Why: Stateless, better for SPA/mobile
   - Benefit: Horizontal scalability, no session storage
   - Tradeoff: Token must be securely stored (localStorage + secure flags)

2. RFC 7807 Error Format
   - Why: Standard, machine-readable errors
   - Benefit: Consistent across all endpoints
   - Tradeoff: Every error response follows specific format

3. Mock-First Development
   - Why: Parallel development, no backend dependency
   - Benefit: UI dev unblocked, full test data control
   - Tradeoff: Must maintain parity with real backend

4. Tenant Isolation at Query Layer
   - Why: Structural enforcement, not just convention
   - Benefit: Prevents accidental cross-tenant leaks
   - Tradeoff: Every query needs tenant filter

5. SSE + Polling Fallback
   - Why: Best of both worlds (real-time + fallback)
   - Benefit: Works on all browsers, graceful degradation
   - Tradeoff: Added complexity (need both implementations)
